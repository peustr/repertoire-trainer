# CLAUDE.md

Repertoire Trainer is a local chess opening trainer (MoveTrainer-style spaced repetition, Stockfish analysis, Lichess explorer and study import). A small Node/Express server serves a no-build vanilla-JS single-page app and stores everything as JSON files. It is meant to run on the user's own laptop, mainly on Windows, and is started by double-clicking `start.bat`.

See `README.md` for the user-facing feature tour and a file-by-file project layout.

## Commands

```bash
npm install            # or `npm ci` for a clean install from the lockfile
npm start              # server on http://localhost:3210, opens the browser
npm run serve          # same, without opening the browser
npm test               # every test/*.test.mjs (node:test) under c8: fails if coverage drops below .c8rc.json, or a test runs over 30 s
npm run test:smoke     # boots the real server on a free port with a temp data dir, hits the API and Stockfish
npm run test:e2e       # Playwright browser tests in test/e2e (first time: npx playwright install chromium)
npm run test:e2e:coverage  # the same, then which lines of public/js they ran (a report, no threshold)
npm run check          # ESLint (no errors, no warnings) + TypeScript over every file
npm run mock-lichess   # fake Lichess on :9099 (set LICHESS_URL and LICHESS_EXPLORER_URL to use it)
node --test --test-timeout=30000 --test-force-exit test/store.test.mjs   # one node:test file
```

Run `npm run check`, `npm test` and `npm run test:smoke` before finishing a change. New tests go in `test/<area>.test.mjs` using `node:test`, which `npm test` picks up automatically. Shared helpers live in `test/helpers/`: `startServer()` boots the real server on a free port with a temp data dir (and `settings` to save there first). Fixtures live in `test/fixtures/`, including `fake-uci-engine.js`, a Stockfish stand-in for `UciEngine`'s `specFor` option (modes for an engine that hangs, refuses a position or crashes, and flags for scripted info lines). Browser behaviour is tested with Playwright in `test/e2e/*.spec.mjs`. The `app` fixture there gives each test its own server and data folder, with seeding helpers, and `playMove()` plays a move on the board. Bug fixes land with a test that fails without the fix, and a failing test must fail, never hang: close sockets, servers and engines with `t.after()` so they go even when an assertion throws (`npm test` also stops any test after 30 s and exits despite leftover handles). `npm test` measures coverage with c8 and fails below the thresholds in `.c8rc.json`: 100% of lines, statements, branches and functions. It counts the server modules, including `server.js` as started by `startServer()`, and the shared modules in `public/js` (the browser-only ones are listed under `exclude` and covered by the browser tests), even files no test loads. New code comes with tests that reach every branch; never lower the thresholds to get a change through. Code that is unreachable is removed, not tested. A `/* c8 ignore */` comment is only for code a test must not or cannot run (opening the user's browser, an incomplete `npm install`) and says why. Coverage has to reach 100% on every CI platform, so cover a platform-dependent path in a way that does not depend on the platform (see the engine tests). CI (`.github/workflows/ci.yml`) runs them on Node 22.12 (exactly the oldest that `engines` accepts), 24 and 26 on Ubuntu and on Node 24 on Windows, plus lint and type check, the browser tests in Chromium on Ubuntu and Windows (with the coverage report of the browser code), a secrets scan and a check that nothing under `data/` is tracked. Raising the minimum Node.js means changing `engines` and the matrix together: a test checks they agree.

There is no build step or bundler. What is in `public/` is exactly what the browser loads. TypeScript only *checks* the JavaScript: every file (`checkJs`), with JSDoc supplying types where inference falls short. Lint rejects `@ts-nocheck`, `@ts-ignore` and `@ts-expect-error`, so no file or line opts out. Fix a type error by describing the shared module's parameters with JSDoc rather than casting at the call sites. Lint flags any promise that is neither awaited, returned nor caught: user actions go through `action()`, and deliberate fire-and-forget calls are written `void promise`. On the server, an unhandled rejection stops the app.

## Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` / `HOST` | `3210` / `127.0.0.1` | Server bind. Keep it on localhost: the API has no auth. |
| `ALLOWED_HOSTS` | none | Extra comma-separated host names the server answers to, besides `localhost`, `127.0.0.1`, `[::1]` and `HOST` |
| `TRAINER_DATA_DIR` | `./data` | Where repertoires, settings, the Lichess token and the cache live |
| `STOCKFISH_PATH` | none | Native Stockfish binary (otherwise `engine/stockfish*`, then the bundled WASM) |
| `LICHESS_URL`, `LICHESS_EXPLORER_URL` | the real Lichess hosts | Point at `test/mock-lichess.js` for offline work |

## Architecture

- **Server (ES modules, like everything else)**: `server.js` (Express REST API, and the `/ws` WebSocket it hands to `engine-socket.js`, which runs the engine requests), `store.js` (JSON file storage with atomic writes), `engine.js` (UCI process manager with two pools: `analysis` for Explore and the eval bar, `tasks` for verdicts, audits, sparring and puzzle search), `lichess.js` (OAuth PKCE, a single-file request queue, explorer disk cache), `puzzles.js` (best-first opponent-mistake search), `settings-schema.js`, `repertoire-format.js` (the repertoire file format, its migration and the checks on writes). The exceptions are `check-node.cjs`, the Node.js version check that `start.bat` runs and `server.js` imports first, which stays CommonJS so a Node.js too old for the rest can still run it and say so, and `check-install.cjs`, which runs right after it and tells `start.bat` to install with `npm ci` when `package-lock.json` changed since the last install.
- **Browser (ES modules)**: `public/js/app.js` is a hash router; each `views/*.js` exports `renderX(root, params)`, appends its page to `root` (a fresh container per navigation, so a view that finishes loading after the user moved on is never shown), and may return a cleanup function. Re-render the current page with `refresh()` from `nav.js`. Wrap async click handlers and callbacks in `action()` from `ui.js`, which disables the button and shows failures as a toast; a global `unhandledrejection` handler is only the backstop. Link to a move with `?line=` or `?moves=` (`movesTo(node)`), never with `node.id`, which changes from one parse to the next. The DOM is built with the hyperscript helper `h('div.class#id', attrs, ...children)` from `ui.js`. Board pages share one panel layout: a `.task` card (prompt, feedback, controls), sections captioned with `panelSection()`, and a "From this position" `toolList()` whose entries come from `views/tools.js`, so every tool says in a sentence what it does. Add a new tool there rather than as a bare button. Third-party modules come from the import map in `public/index.html`, served out of `node_modules` under `/vendor/...`.
- **Shared modules**: `public/js/constants.js`, `protocol.js`, `moves.js`, `pgn.js`, `repertoire.js`, `srs.js`, `session.js`, `opponent.js`, `puzzle-utils.js` and `outbox.js` run in **both** the browser and Node; the server and the tests import them directly. Keep them free of DOM APIs, and only import bare specifiers that resolve in both places (currently just `chess.js`, which is in the import map *and* `node_modules`). `constants.js` holds `START_FEN`, `positionKey`, `scoreToCp` and the Lichess speeds and rating groups: import them from there rather than writing them out again. To play one move from a position, use `playMove()` from `moves.js` (UCI or SAN) rather than a chess.js instance of your own.

## Conventions and gotchas

- **Settings come from `settings-schema.js` alone.** To add a setting, add one field there (type, range, default, label, help). Server validation, defaults and the Settings page all derive from it. Fields that need Stockfish restarted get `restart: true`, which puts them in `ENGINE_KEYS`. Fields the mistake finder uses get `search: '<option name>'`, and `finderOptions()` turns the settings into its options (percentages become fractions). A schema test checks that every field has a label and a default.
- **Card keys are stored user data.** A card is keyed by `positionKey(fen)|uci` (`repertoire.js` `cardKey`), and progress in `data/repertoires/*.json` is keyed the same way. Changing `positionKey`, `cardKey` or line hashing silently resets everyone's progress. Don't, unless a migration comes with it.
- **Lichess etiquette is deliberate.** All Lichess calls go through the one-at-a-time queue of the app's single client, which `server.js` makes with `createLichessClient()` and passes to whatever needs it (the mistake search gets it as `lichess`). Every request, sign-in and token checks included, is made through its `call()`, which waits out the 61 s pause that follows a 429. Never make a second client in the app, fire parallel requests or bypass the cache. Tests make their own client with a temp `dataDir`, the mock's URLs and a short `rateLimitPauseMs`.
- **The Lichess token never reaches the browser.** It lives in `data/lichess.json`, and `lichess.status()` (what `/api/lichess/status` returns) deliberately leaves it out. Keep it out of any new response or log line.
- **Other websites must not reach the server.** `refusal()` in `server.js` rejects requests whose `Host` is not a local name (DNS rebinding) and requests or WebSockets whose `Origin` is another site. Every route and the `/ws` socket pass through it. Don't add routes ahead of it or loosen it.
- **Engine jobs must not hang or be dropped.** In `UciEngine`, a search silent for `stallTimeout` (45 s) is asked to stop, and the engine is replaced if it does not answer. `submit()` refuses (with a 400) positions Stockfish cannot search (`checkFen`: no kings, more than 32 pieces, the side not to move in check) and values that would smuggle in a UCI command. A search Stockfish refuses anyway (`info string CRITICAL ERROR`, after which it answers nothing) fails at once and the engine is replaced. `restart()` (any `restart: true` setting) lets the running search finish and moves queued ones to the new process. `start()` never throws: an engine that cannot be launched (on Windows `spawn` throws for a file that is not a program) fails its start like any other, so a bad engine path in Settings cannot stop the app. A write to an engine that has just died fails with EPIPE, so the engine's stdin keeps an `error` listener. Engine paths on network shares are never run or even checked. `test/engine.test.mjs` covers all of this with the fake engine.
- **The training rules live in `public/js/session.js`**: which moves a pass quizzes, how answers and hints are graded, and what each result does to the schedule (`gradePass`, `gradeCard`). Views call it with the user's settings and never re-implement it. The scheduler in `srs.js` holds no settings of its own: `learned`, `promote`, `demote` and `intervalFor` take the schedule (`scheduleOf(settings)`), and `DEFAULT_SCHEDULE` is the one copy of the defaults. Change a rule there, with a case in `test/session.test.mjs`.
- **Progress saves go through `saveCards()`** (`public/js/store.js`), never straight to `api.progress`. It queues them in the outbox (`public/js/outbox.js`, kept in `localStorage`), which retries until the server takes them. Each save has a `saveId`, so the server applies a retried save only once. Never make `saveCards` reject or bypass the queue: a lost save is lost training.
- **Browser engine requests time out.** `engine-client.js` gives up after 90 s without a message (180 s for the mistake search). `analyse()` reports failures to its `onError` argument: pass one that shows the error where the result would have gone.
- **The repertoire file format is defined once, in `repertoire-format.js`**: the `RepertoireFile` typedef, `SCHEMA_VERSION`, and `migrate()`, which `store.js` runs on every read (files from before versions are version 1; a file from a newer trainer is refused, not half-read). PUT and PATCH …/progress bodies are checked against it (`checkRepertoireInput`, `checkProgress`) and refused with a 400. The edit form's PUT names the version it started from (`baseUpdatedAt`), and is refused with a 409 once the file has moved on, so a chapter added meanwhile is never written over. To change the format, raise `SCHEMA_VERSION`, add a step to `migrate()`, update the typedef, and test it with a file in the old format. The browser's outbox drops a save the server refuses with a 400, so a check must accept everything the browser really sends: `test/repertoire-format.test.mjs` pins that down.
- **The engine WebSocket's messages are listed in `public/js/protocol.js`** (`REQUEST`, `REPLY`, and a typedef per message). `engine-socket.js` and `engine-client.js` use those names, never string literals. The server answers a request type it does not know with an error, so a page never waits for its timeout.
- **Data files go through `store.js`.** `writeJsonAtomic` writes a temp file, flushes it to disk, keeps the previous version as `<file>.bak` (except for `lichess.json`: a replaced or disconnected token must not stay on disk), and retries the rename while a sync client or scanner holds the file. `readJson` never overwrites a damaged file: it keeps it as `<file>.corrupt-<time>` and restores the `.bak`. A deleted repertoire is moved, with its `.bak`, to `data/trash/<id>-<time>/`. Don't read or write data files with `fs` directly.
- **Dependencies are pinned to exact versions**, each the newest release at least 14 days old when added (Dependabot waits as long). A test checks that `package.json` pins them and that the lockfile matches.
- **IDs are validated** (`/^[a-z0-9-]+$/` in `store.repFile`) before they touch the filesystem. Keep that check on any new route that builds a path. A repertoire's id is its file name, whatever the file says: the library skips, with a console warning, a file whose name is not an id or that does not hold an object.
- API handlers use the `wrap`/`wrapAsync` helpers: return a value for JSON, `null` for 404, or throw an error with `.status`. The last handler in `server.js` answers errors raised before a route runs (a body that is not JSON or is too large) in the same JSON shape.
- User-facing text is plain, professional British English ("Practise", "analyse", "colour"). Write errors the user can act on ("Connect your Lichess account first."), not internal jargon.
- Match the existing style: 2-space indent, single quotes, semicolons, short top-of-file comments that say what a module is for.
- The project is GPL-3.0-or-later because it ships Stockfish and chessground.

## Never commit

`data/` holds personal repertoires, progress, settings and **`data/lichess.json`, a live Lichess OAuth token**. It is gitignored, and CI fails if anything under it is tracked. Native engine binaries in `engine/` are also ignored; only `engine/README.txt` is tracked. When writing tests, point `TRAINER_DATA_DIR` at a temp dir (`startServer()` and `test/store.test.mjs` do) rather than using `./data`.
